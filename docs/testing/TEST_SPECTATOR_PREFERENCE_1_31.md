# 1.31 spectator preference availability

The spectator checkbox was disabled by spectator_available(), which is set only after startup verifies the ReSkate profile, Skate image, four private spectator signatures, render-hook ownership and successful hook installation. Every verification failure previously emitted one generic log message. A displayed mod version of 1.30 does not establish which ReSkate DLL, game image or render-hook chain was loaded. The affected installation has not been inspected, so its precise failed check is unconfirmed.

Version 1.31 removes runtime readiness as a restriction on selecting and saving the spectator preference. It reports the specific initialization failure in the panel and log, including signature RVA, render-hook owner or hook installation failure. The redundant version-label and whole-game-image gates are removed: verified spectator-local functions now suffice to attempt hook installation. Enabling the preference retries initialization if the startup attempt was unavailable. Spectator function signatures and runtime ownership checks remain in place before camera/pose memory access. Enabling the preference cannot make an incompatible runtime layout work.

Gameplay acceptance: on the affected rolled-back 2.0.7 installation, select the checkbox, restart and confirm it persists. Read any runtime-unavailable status, then join a party and spectate using the First Person binding. Verify first-person entry, follow-camera return and watched-player switching. Existing working installations should behave as before. The combined 1.32 update was confirmed working on both machines by the user on 14 October 2026.
